# Release notes

## Changes

- the `GRYLibrary`-dependency of `ConSurvBackend` and its tests was bumped from `2.1.6` to `2.1.8`
- the RTSP-transport is now explicitly specified as a product-wide invariant: ingestion runs over TCP only, there is no per-camera or global switch to use UDP; the decision is captured in the new openspec `openspec/specs/transport-protocol/spec.md`, in the backend-reference-article `ConSurvBackend/Other/Reference/ReferenceContent/Articles/RtspTransport.md` and as architectural decision D002 in `Other/Reference/Technical/09_Architectural-Decisions.md`
- the probe in `CameraManagementService.IsRtspAvailable` now matches the real camera-processes by requesting `-rtsp_transport tcp`, so that sources which only speak UDP surface the correct `461 Unsupported transport` error immediately instead of producing a probe-result which disagrees with the behaviour of the subsequent processes
- the error-message produced on a failed RTSP-probe now includes the `ExitCode` of `ffprobe`, which makes it possible to distinguish a timeout (empty stdout/stderr, exit-code set by the timeout-handler) from a real protocol-level rejection by the camera
- the central reference-document `Other/Reference/Reference.md` now contains a `## Features`-section with the complete list of user-facing features (`feat-1` to `feat-26`), as required by the new openspec `openspec/specs/common-projects-structure-features/spec.md`
- the findings-table in `Other/Reference/Reference.md` was extended by the entries `CSV-45` (plan to address the deferred architectural refactors each in a dedicated branch/change) and `CSV-46` (the transport-protocol-spec clause which maps `461 Unsupported transport` onto an `Unavailable`-camera-state has no clearly matching handler yet)
