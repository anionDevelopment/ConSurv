# Release notes

## Changes

- the fonts "Roboto" and "Material Icons" are delivered with the application instead of being loaded from an external font-service, so the user-interface does not depend on the availability of that service and no request leaves to it
- added visual-regression-tests for the camera-list and for the page of a single camera
- the user-menu is now at the same position in every browser. It was located 20 pixels higher in firefox than in chromium and in webkit, because the gap between its title and its first entry was a line-break inside a flex-container, and a line-break is a flex-item which the engines give a different height. The gap is a margin now
- the visual-regression-tests additionally check that all browsers lay every checked page out the same way, which the comparison of a screenshot with the baseline of its own browser can not detect
- the color-scheme of the user-interface (system, light or dark) can be chosen in the header of every page and is stored per user in the new table "UserSettings", so the choice is applied again after a new login and on another device. A user who never chose anything keeps "system", which follows the setting of the operating-system of that user
- The scripts of the codeunits now use the current api of ScriptCollection (the api "TasksForCommonProjectStructure" which they used does not exist anymore, so they were not runnable)
- Updated the versions of the used images
- Removed the configuration of GitVersion, which is not used anymore
- Fixed the container-entrypoint script to export the environment-variable under the name the backend actually reads ("ISRUNNINGINCONTAINER" instead of "IsRunningInContainer"), so the backend now correctly detects that it runs inside a container
- Fixed a typo in the name of the initialization-callback "SetInitializationInformationAction" (previously "SetInitialzationInformationAction")
- Updated GRYLibrary to version 2.0.31
- The backend and its testcases now declare their runtime-identifiers ("win-x64", "linux-x64", "linux-arm64") directly in the project-files, so the build-script does not have to derive and pass them anymore
- Updated the SCBuilder-image to v1.2.9
- A camera-name is now also rejected when it contains a control-character (which includes carriage-return and line-feed), an invisible character or a format-character, not only whitespace and the already forbidden punctuation-characters, because such a name would be indistinguishable from another one in the user-interface or could be used to forge additional lines in logs and command-lines
- Added testcases for the color-scheme-setting of a user and for the derivation of camera-ids from stream-URLs
- Added Greek ("el") as a selectable ui-language of the frontend. Only "Username" and "Password" are translated so far as an example for the translator; the remaining strings still fall back to English until translated
- the user-settings-page contains a culture-selector (the component "@aniondev/ngx-culture-selector") which lets the user choose between English, German and Spanish. The offered cultures are a fixed list for now and the chosen culture is not applied to the application yet, because the selector is only tried out at the moment
- Fixed the unit-tests of the camera-page and of the camera-list-page, which failed because their mock of the storage-service did not provide the method "hasAccessToken" which the theme-service calls
